## 裁判格式故障

首轮 100 条只有 90 条评分合法，另 10 条格式错误集中在拒答或部分回答。首轮有效评分的正确性均为 2；排除这些格式失败会使结果偏乐观。

对 `single_hop_010` 诊断重试保留原始输出，裁判实际返回了 `{"correctness": 0, "faithfulness": 0, "relevance": 2}`，缺少嵌套对象与理由。记录为 `data/eval_results/day7_judge_format_diagnosis.json`。补充格式示例后对同一批生成答案统一重评，不混合两种提示词的分数；旧记录均保留。此次重评的数值变化包含裁判重新调用的波动，不把变化全部归因于格式示例。

## 待人工判断的裁判错误候选

题目 `single_hop_010`：按 Object public-read 定义，匿名用户可以写入吗？

实际提供的资料：

1. Object public-read-write 允许匿名读写。
2. Bucket public-read-write 允许匿名读写。
3. Bucket public-read 允许匿名读，写入需要所有者或授权用户资格。

实际回答：资料未说明。

裁判给正确性 0、忠实度 0、相关性 2。忠实度理由认为资料 3 已经说明写入规则。但资料 3 的对象是 Bucket，题目对象是 Object，实际资料没有 Object public-read 的规则。

助手建议忠实度记 2：仅就实际片段而言，拒答合理；正确性仍为 0，因为完整题集的参考答案可回答、系统未给出答案。该建议待用户审核，保留原始裁判分数，没有改写它来提高汇总。

讨论中用户认为 Bucket public-read 片段可以作为 Object public-read 的依据。助手说明完整知识下两者规则相同，但严格限于当前片段时缺少跨对象通用规则；也承认把该例称为明确裁判错误过于绝对。该证据边界尚未获得用户明确评分，不能将用户的“继续”记录为接受助手建议或完成这条人工标注。
